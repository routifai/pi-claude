The common item format

Every executor — ClaudeSDKExecutor, PiExecutor — takes the same input type and yields the same event type, regardless of what's underneath.

This is the only shape the runner, the Session, and the Postgres store ever see. Whatever Pi says over RPC, whatever Claude's SDK streams back — both get folded into Message objects before anything is recorded. Neither harness is aware this translation is happening.

Two native worlds underneath

Before translation, each harness keeps its own state, in its own format, in its own place.

Pi's actual turn-by-turn conversation lives inside the running pi --mode rpc process — PiExecutor talks to it over that RPC stream, it never reads a flat file. Claude Code keeps its own append-only .jsonl rollout per session on disk; this is the exact file a documented Omnigent bug references when a sandbox fork can't reach it (see below).

Extending to long-term: Hindsight

The Postgres store above is the short-term, per-conversation record. Long-term recall across conversations is a separate store, wired in as ordinary tool calls.

Agent callshindsight_recall
→
Intercepted byOmnigent runner
→
Executed viahindsight-client
→
Own storeHindsight Postgres

Two Postgres databases doing two different jobs. The session store above records every turn, every conversation, forever, harness-agnostic. Hindsight's bank stores distilled facts, reachable across conversations, only when the agent decides to call recall/retain. They don't share tables — only the same bank_id convention ties Pi's and Claude's calls to the same long-term memory.

Takeaways

  • Both harnesses' native state — Pi's RPC session, Claude's .jsonl rollout — stays exactly where it is. Omnigent never merges them directly.
  • Translation happens once, into omnigent.Message, and that's the only shape the Session and the database ever store.
  • switch-agent is the real mechanism for carrying conversation across a harness switch — carry_history: "1" confirms it. Driving executors directly, like our prototype did, skips it entirely.
  • Storage is Postgres or SQLite only, schema-based. No native Mongo path — mirroring to Mongo is the Control Plane's job, not Omnigent's.
  • Hindsight adds a second, separate Postgres store for long-term recall, reachable by any harness that shares the same bank_id.
