Choosing the Harness Adapter

Three ways to implement the layer between the Control Plane and the Harness Pod: Agent Client Protocol, Vercel's AI SDK harness layer, and Omnigent. Slight lean toward Omnigent below — with the reasoning shown, not asserted.

On "you get access to their native stuff"

"…because it gives you the ability to run any version of these harnesses and you get access to their native stuff"

Half right, worth tightening. Native access is real: Omnigent doesn't reimplement Claude Code or Pi, it drives the actual SDK/CLI — ClaudeSDKExecutor runs the real Claude Agent SDK, PiExecutor literally shells out to pi --mode rpc. Whatever's installed locally is what runs, so native tool-calling, skills, and subagents all come through untouched.

But that part isn't unique to Omnigent. Vercel's harness layer does the exact same thing from Node — it also spawns the real CLI/SDK per harness rather than reimplementing it, and its sandbox images pin specific harness versions just as deliberately. Version pinning and native access are properties of both frameworks; only ACP alone falls short here, since a protocol spec doesn't run anything by itself.

The reasons that actually favor Omnigent for this diagram are narrower: it's Python, sitting in the same runtime as LiteLLM and Llama Index already in the Harness Pod, so there's no cross-language hop on every call. It's self-hosted with no platform dependency. And it already ships the session/collab/UI machinery this stack needs, rather than leaving it to be built on top of a bare adapter.

Verdict

Lean Omnigent for the Harness Pod / execution side of this diagram — not because it uniquely unlocks native harness access, but because of what sits next to it.

Same runtime as LiteLLM & Llama Index — no Node↔Python hop per call
Self-hosted, Apache-2.0 — no dependency on Vercel's sandbox platform
Widest harness list, including Databricks-oriented executors
ACP still worth adopting as the wire contract at the Harness Adapter boundary, independent of which runtime sits behind it

Caveat: Omnigent wants to own sessions and history itself. Plugging it in means reconciling its session model with the Control Plane's Session Authority + Mongo — not routing around them.
